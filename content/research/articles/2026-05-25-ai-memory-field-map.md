# AI memory is a field, not a feature

AI memory products are frequently compared as if they solve the same job. That
collapses the most important distinction: memory is not a single feature. It is
a system of write paths, retrieval paths, temporal updates, source boundaries,
governance, and evaluation.

MemoryBench treats the space as five live research lanes:

1. Memory APIs for writing and recalling user or application memory.
2. Temporal graph memory for evolving entities, relationships, and provenance.
3. RAG frameworks for grounded retrieval and orchestration.
4. Retrieval substrate for vector, hybrid, and reranking infrastructure.
5. Stateful agent runtimes for long-lived agents with managed context.

The daily research watch should therefore avoid a generic "AI memory news"
bucket. Every captured item needs a layer assignment, source link, uncertainty
note, and expected benchmark impact.

## What Counts As Evidence

For this site, a serious evidence item is one of:

- A public repository release, commit signal, issue milestone, or documented API change.
- A paper, benchmark, evaluation protocol, or reproducible experiment.
- A vendor or project announcement that can be checked against docs or code.
- A failure case, regression, or contradiction that affects a scorecard.

The website can be polished, but the corpus must stay inspectable in GitHub.
Markdown remains the source format so an agent, reviewer, or researcher can
audit history without needing the frontend.
