## Design Context

### Users
Personal AI OS operators, AI-memory researchers, and engineering workers who
compare local memory systems, validate evidence, and decide which components
belong in the retained GBrain + Hindsight runtime.

### Brand Personality
Precise, evidence-first, operational. The interface should feel like a local
research command bench: dense enough for repeated use, calm enough for audit
work, and explicit about proof boundaries.

### Aesthetic Direction
OpenDesign-derived Memory OS workbench. Use off-white paper fields, ruled
grids, green/teal infrastructure tones, gold evidence accents, coral gaps, lime
selection markers, circular cartography, and dossier-like proof panels. Avoid
marketing heroes, decorative gradients, nested cards, and generic SaaS chrome.

### Design Principles
- Preserve the app as a usable first-screen workbench, not a landing page.
- Make derived runtime and coverage values visible before decorative content.
- Keep the memory boundary circle and selected-project docket as the primary
  visual anchors.
- Separate evidence, support signal, project fit, and capability scores so the
  model remains auditable.
- Maintain responsive access to search, view switching, current metrics, and
  project detail on small screens.
